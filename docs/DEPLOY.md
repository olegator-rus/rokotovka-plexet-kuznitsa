# Развёртывание из репозитория

Документ описывает, как поднять стенд с нуля, имея только этот репозиторий и фид каталога. Порядок проверен на чистой
папке на отдельной машине: результаты проверки приведены в конце.

Готовый стенд работает по адресу <https://softline.plexet.ru>. Развёртывать свой нужно, только если вы хотите проверить
воспроизводимость или подключить другой каталог.

## Что понадобится

| Что | Требование |
|---|---|
| Сервер | Linux, 4 процессора, 16 ГБ памяти, 30 ГБ диска. Видеокарта не нужна |
| Программы | Docker с Compose. Go, Node и Python ставить не нужно: всё собирается в контейнерах |
| Сеть | Выход в интернет для образов, весов моделей (около 4,5 ГБ с Hugging Face) и сертификата; открытые порты 80 и 443 |
| Адрес | Домен, который указывает на сервер. Без своего домена подойдёт `<IP через дефисы>.sslip.io`, например `203-0-113-10.sslip.io` |
| Фид | Выгрузка каталога магазина `Mindbox.yml.xml` (можно `.xml.gz`). В репозиторий она не входит: это данные заказчика |
| Ключ модели | Необязателен. Без него работают поиск, допродажа, трассировка и раздел «Доказательства»; ИИ-консультанту, разбору ТЗ, агенту SearchOps и трудным запросам нужна языковая модель с OpenAI-совместимым API |

Всё остальное лежит в репозитории: соответствие полей фида (`data/softline/mapping.yaml`), словарь, адреса семейств,
документы совместимости, акции, классы допродажи, база знаний консультанта, наборы оценки и тестовый трафик.

## Быстрый путь: одна команда

```bash
git clone <адрес репозитория> searchops && cd searchops
DOMAIN=203-0-113-10.sslip.io deploy/bootstrap.sh /путь/к/Mindbox.yml.xml.gz
```

Скрипт `deploy/bootstrap.sh` делает всё по порядку:

1. Создаёт `.env` в корне, если его нет: случайный пароль базы, случайный токен бэк-офиса, домен из `DOMAIN`.
2. Кладёт фид в `data/softline/feed/` и конвертирует его в файлы для импорта.
3. Собирает образы и поднимает PostgreSQL, OpenSearch и сервис моделей. Ждёт, пока модели скачаются и загрузятся.
4. Импортирует каталог в базу и в поисковый индекс вместе с векторами, строит словарь подсказок.
5. Поднимает API и веб-сервер с автоматическим сертификатом и проверяет `/api/health`.

После этого витрина открывается по `https://<DOMAIN>`, вход в бэк-офис выполняется демо-кнопками на странице `/login`.

Чтобы подключить языковую модель, впишите в `.env` ключ и перезапустите API:

```bash
# в .env: LLM_PROVIDER, LLM_BASE_URL, LLM_MODEL, LLM_FOLDER_ID, LLM_API_KEY (описание — в .env.example)
docker compose --env-file .env -f deploy/docker-compose.yml up -d api
```

Ключ можно передать и сразу, переменными окружения при первом запуске скрипта: он запишет их в `.env`.

## Демо-данные

Сразу после импорта журнал поиска пуст, поэтому первый экран SearchOps и часть вкладок «Доказательств» показывают
«прогон не запускался». Наполнить их можно тем же скриптом с ключом `--demo` (нужен ключ языковой модели):

```bash
deploy/bootstrap.sh /путь/к/Mindbox.yml.xml.gz --demo
```

Ключ `--demo` добавляет два шага:

- проигрывает тестовый трафик `data/softline/searchops_flow.jsonl`: 150 запросов из эталонов заказчика, прогона сайта и
  синтетики по каталогу. В журнале появляются неудачные поиски, с которыми работает агент;
- прогоняет наборы оценки «по цели»: эталоны, примеры из кейса, соседей эталонов, набор понимания и отложенный набор.
  Экран «Доказательства → На данных заказчика» после этого показывает числа.

Метрики на журнале поиска (вкладки «Метрики», «Контроль улучшений», «Вклад компонентов») считаются по набору, который
собирается из накопленного журнала и размечается кликами и моделью-судьёй. На свежем стенде журнал короткий, поэтому
эти вкладки наполняются по мере работы или командами из раздела «Воспроизводимость и проверка» в README.

## То же по шагам

Если скрипт не подходит, те же действия выполняются вручную. Все команды запускаются из корня репозитория.

```bash
# 1. Настройки
cp .env.example .env
#    заполнить: DOMAIN, ACME_EMAIL, POSTGRES_DB=kuznica, POSTGRES_USER=kuznica,
#    POSTGRES_PASSWORD и BACKOFFICE_TOKEN (openssl rand -hex 24), TRUSTED_PROXIES=172.16.0.0/12,
#    AUTH_REQUIRED=on, DEMO_LOGIN_BUTTONS=on; ключи модели — по желанию

# 2. Фид → файлы для импорта (только стандартная библиотека Python)
mkdir -p data/softline/feed
gunzip -c /путь/к/Mindbox.yml.xml.gz > data/softline/feed/Mindbox.yml.xml
docker run --rm -v "$PWD":/w -w /w python:3.13-slim python scripts/data/softline_feed.py

# 3. Образы и сервисы данных
DC="docker compose --env-file .env -f deploy/docker-compose.yml"
$DC build
$DC up -d db opensearch ml          # дождаться, пока ml станет healthy: docker ps

# 4. Каталог → PostgreSQL и OpenSearch, словарь подсказок
$DC run --rm api import
$DC run --rm api suggest-build

# 5. API и веб-сервер
$DC up -d api web
```

## Как проверить, что всё работает

```bash
DC="docker compose --env-file .env -f deploy/docker-compose.yml"
$DC ps                                           # пять сервисов, у db, opensearch, ml и api статус healthy
$DC exec -T api wget -qO- http://localhost:8080/api/health

# поиск с опечаткой и условиями из запроса
curl -s https://<DOMAIN>/api/search -H "Origin: https://<DOMAIN>" -H 'Content-Type: application/json' \
  -d '{"query":"касперкий на 50 компов на год"}' | head -c 600
```

В ответе поиска должны быть поле `total` больше нуля и карточки Kaspersky с условиями «50 устройств» и «1 год».
В браузере: главная страница, запрос «астра линукс», переключатель «Трассировка» внизу страницы.

## Частые вопросы

**Порты 80 и 443 заняты.** Задайте в `.env` другие: `HTTP_PORT=8081`, `HTTPS_PORT=8443`. Автоматический сертификат при
этом получить нельзя: Let's Encrypt проверяет домен по стандартным портам. Для проверки на нестандартных портах
используйте `DOMAIN=localhost`, тогда веб-сервер выпустит локальный сертификат.

**Сколько ждать.** Сборка образов занимает несколько минут. Первый старт сервиса моделей скачивает около 4,5 ГБ весов.
Дольше всего идёт импорт: векторы для 12,5 тысячи продуктов считаются на процессоре, на проверке это заняло 1 час 57 минут на
4 процессорах, занятых наполовину. Скрипт в это время ничего не печатает, прогресс виден по журналу сервиса моделей:
`docker compose --env-file .env -f deploy/docker-compose.yml logs --tail 5 ml`.

**Другой каталог.** Каталог подключается файлом соответствия полей. Образец с пояснениями лежит в
`data/mapping.example.yaml`, действующий файл для фида магазина — `data/softline/mapping.yaml`. Путь задаётся
переменной `DATA_MAPPING`, по умолчанию `/data/softline/mapping.yaml` внутри контейнера.

**Запуск без данных заказчика.** Если фида нет, решение можно посмотреть на учебном каталоге из `data/mock/`: порядок
локального запуска описан в разделе «Запуск» README.

**Обновление.** После `git pull` достаточно `$DC build && $DC up -d`. Повторный импорт нужен, только если изменился фид
или файл соответствия. Словарь, документы совместимости, акции и база знаний читаются при старте API.

**Остановка и удаление.** `$DC down` останавливает сервисы, данные остаются в томах. `$DC down -v` удаляет и тома.

## Результаты проверки

Порядок из раздела «Быстрый путь» выполнен в чистой папке, куда попали только файлы открытого репозитория и фид.

| Шаг | Результат |
|---|---|
| Создание `.env` | создан, пароль базы и токен сгенерированы |
| Конвертация фида | 20 секунд, 136 040 предложений |
| Сборка образов | прошла; Go, Node и Python на машине не установлены |
| PostgreSQL, OpenSearch, сервис моделей | поднялись, сервис моделей готов через 4 минуты после старта (веса скачаны) |
| Импорт каталога с векторами | 1 час 57 минут: 136 040 документов в индексе, 12 538 векторов. Почти всё время ушло на векторы, запись индекса заняла 70 секунд |
| Подсказки, API, веб-сервер | поднялись, `/api/health` отвечает `ok` по базе, поиску и сервису моделей |
| Поиск на свежем стенде | «касперкий на 50 компов на год» → 15 продуктов, первым Kaspersky Endpoint Security Стандартный; «astra linux» → Astra Linux Special Edition; «fcnhf kbyerc» → Astra Linux; «сервер» → стоечные серверы |

Число документов и векторов совпало с основным стендом. Проверка шла на машине с 4 процессорами, где в это же время
работал основной стенд, поэтому импорту доставалась примерно половина процессора. На свободной машине того же размера
импорт должен пройти быстрее, но закладывайте на него от одного до двух часов.

Проверка нашла одну ошибку в скрипте: папка с фидом создавалась с правами только для владельца, и сервер в контейнере
не мог её прочитать. Ошибка исправлена, скрипт в репозитории уже с исправлением.

Ключ `--demo` и работа с языковой моделью в этой проверке не запускались: свежий стенд поднимался без ключа модели.
Основной стенд поднят из тех же образов и того же файла `deploy/docker-compose.yml`. Каталог и индекс на него были
перенесены с рабочей машины готовыми, а не посчитаны импортом на месте.
