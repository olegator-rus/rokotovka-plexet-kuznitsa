# Матрица требований

Требования кейса «Умный поиск на сайте»: десять пунктов. Ниже — три уточнения заказчика с установочной встречи и
то, что сделано сверх требований: ИИ-консультант и поиск по ТЗ, которые заказчик назвал гипотезой. Каталог везде —
фид магазина (136 040 предложений).

Для каждого требования указаны код (файл и функция), автотест и доказательство: экран, число из прогона и команда
воспроизведения. Имена файлов, функций и тестов взяты из кода. Числа взяты из сохранённых прогонов; те же числа
показывает экран «Доказательства → На данных заказчика» (`/proofs?tab=feed`), а методика описана в
[EVALUATION.md](EVALUATION.md).

Статусы:
- **полное** — есть код, автотест и воспроизводимое доказательство: отчёт с числами или проверка данных тестом;
- **без отчёта** — код и тесты есть, работу видно на экране и можно перепроверить командой, но сохранённого отчёта
  с числом качества нет;
- **частично** — часть требования данными заказчика не закрывается (причина в строке).

## Как запускать проверки

| Что | Команда | Что нужно |
| --- | --- | --- |
| Go-тесты | `cd backend && go test ./services -count=1 -run '<имя теста>'` | ничего, кроме Go |
| Тесты загрузчиков данных фида | `cd backend && go test ./externalApi/catalogsource -count=1 -run '<имя>'` | файлы `data/softline/*.csv` |
| Тесты фронта | `cd frontend && pnpm test` | Node 22, pnpm |
| Сквозные тесты | `cd e2e && pnpm exec playwright test tests/<файл>.spec.ts --project=flows` | API на фиде на :8088, эмбеддер на :8089, Vite (см. README) |
| Оценка «по цели» | `cd backend && DATA_SOURCE=generic DATA_MAPPING=../data/softline/mapping.yaml go run . eval --set etalon,tz,neighbors,understanding --configs live` (холодный прогон и сравнение с базовыми вариантами: `--cold --configs BM25,B1,B2,live`; отчёт: `--report <каталог>`) | Postgres, OpenSearch, импортированный фид, эмбеддер |
| Оценка подбора | `cd backend && DATA_SOURCE=generic DATA_MAPPING=../data/softline/mapping.yaml go run . guide-eval --runs 3 --report <файл>` | то же и ключ модели |
| Скрипты оценки через HTTP | `API=http://127.0.0.1:8088 python3 scripts/eval/<скрипт>.py` (`--out <путь без расширения>` пишет `.md` и `.json` у `upsell_eval.py`, `suggest_prefix_eval.py`, `searchops_snapshot.py`) | работающий API на фиде; для `searchops_snapshot.py` — демо-вход (`DEMO_LOGIN_BUTTONS=on`) |

Наборы для `go run . eval` и `guide-eval` лежат в репозитории (`data/softline/eval/`). Часть Python-скриптов читает
исходные наборы из рабочей папки команды, которая в открытый репозиторий не входит: это пары склонений и набор
«продление и по запросу». Их итоги приведены в таблицах ниже. Числа наборов «по цели» показывает экран
«Доказательства → На данных заказчика»: он читает прогоны `go run . eval` из базы.
