# Требования заказчика → где в продукте

Семь требований к агенту и пять ролей, названные организаторами. Для каждого — экран или метод и чем
подтверждено. Цифры — на собственных mock-данных, прогоны и методика — в [EVALUATION.md](EVALUATION.md).

Экраны: «Поиск» `/search`, «До / После» `/compare`, «Аналитика» `/analytics`, «SearchOps» `/searchops`,
«Изменения» `/changes`, «Экономика» `/costs`.

## Семь требований

| # | Требование | Где | Чем подтверждено |
| --- | --- | --- | --- |
| 1 | Понимать смысл запроса: синонимы, опечатки, сленг, аббревиатуры | «Поиск»: строка «Мы поняли запрос так» с чипами, исправление с возвратом к введённому, трасса шага `normalize`; `POST /api/search` | test, NDCG@10 B3 против B2: опечатки 0,991 / 0,820, раскладка 1,000 / 0,836, сленг 0,976 / 0,932. Неизвестный сленг (`alias_gap`) 0,636 → 0,900 после правки агента (B4) |
| 2 | Релевантные результаты без точного совпадения | «Поиск»; «До / После» | Пустые выдачи B0 83,1 % → B3 8,1 %; NDCG@10 0,164 → 0,870 (B4 — 0,888). Аналоги («аналог фотошопа»): 0,514 у B2 → 0,835 у B3. Ложное спасение 100 % у B2 → 16,7 % у B3 |
| 3 | Учитывать контекст: категорию, сегмент, историю клиента | «Поиск»: переключатель клиента; трасса — слагаемое `context` в скоре | «продлить антивирус»: у клиента с купленным KSOS на 10 ПК первым его продление, у клиента без истории — общая выдача (demo-набор, проверено вручную, в метриках test не участвует). Продления на test: NDCG@10 0,851 у B3 против 0,516 у B1 |
| 4 | Ранжировать по релевантности, популярности, маржинальности | Бизнес-слой: `0,80·relevance + 0,10·popularity + 0,05·margin + 0,05·context`; разложение скора в трассе | Механизм работает и виден в трассе каждой позиции. Веса не обучены, отдельный вклад бизнес-слоя в метрики **не измерялся**; маржа в mock-данных — суррогат |
| 5 | Подсказки: автодополнение, исправление опечаток, связанные запросы | «Поиск»: выпадающие подсказки (`GET /api/suggest`), строка «Показаны результаты по запросу … Искать как введено», блоки «Похожие запросы» и «С этим покупают» | Опечатки и раскладка — см. п. 1. Качество подсказок отдельной метрикой **не измерялось** |
| 6 | Анализировать неудачные поиски: что ищут и чего нет в каталоге | «Аналитика» — проблемные запросы; «SearchOps» — запуски агента, очередь, задачи продукт-менеджеру | Запуск `01a20fe2-…`: 233 неудачных запроса из 384 за 30 дней → 40 кластеров → 8 разобраны за 2 мин 40 с, 30 ₽. Задачи: chatgpt, figma, notion, visio — спрос без предложения; revit, acronis — есть аналог. Запуск `01a21002-…` (45,11 ₽): «кис», «антивирус для офиса» — `RANKING_FAILURE` (товар есть, но стоит не первым), winrar — `ASSORTMENT_GAP` |
| 7 | Логировать действия и показывать аналитику | Журналы `search_events`, `behavior_events`, `search_traces`, `llm_usage`; «Аналитика»; `GET /api/analytics` | На 30 днях mock-логов: пустых 27,6 % поисков, без клика 38,2 % непустых, заказ после поиска 7,9 %, воронка 3 074 → 1 383 → 477 → 245 |

«Другие действия агента» из ТЗ организаторов ещё не известны.

## Пять ролей

| Роль | Что получает | Где | Чем подтверждено |
| --- | --- | --- | --- |
| Клиент | Находит товар с первого запроса, понимает, почему выдача такая; если товара нет — аналоги и кнопку менеджера | «Поиск» | Точные запросы первыми — 97,8 % (B3); пустые 8,1 %; нарушения условий лицензии в топ-10 — 21,7 % запросов (нерешённое) |
| Менеджер e-com | Где теряем покупателей; очередь правок словаря, проверенных прогоном; версии правил и откат | «Аналитика» (роль e-com), «SearchOps» → очередь, «Изменения» | Принятая правка «зуп»: целевой кластер 0/4 → 4/4, регрессия 0 из 220; на test B3 → B4: 4 улучшения, 0 ухудшений |
| Продукт-менеджер | Что ищут и не находят: кластеры спроса без предложения, востребованные аналоги | «Аналитика» (роль продукт-менеджера), задачи агента | Задачи `ASSORTMENT_GAP` и `SUBSTITUTE_AVAILABLE` из трёх живых запусков агента |
| Контент-менеджер | Какие карточки и словари править | «Аналитика» (роль контент-менеджера) | Блок строится из предложений агента. `CONTENT_GAP` агент поставил один раз (запуск `01a21002-…`, «счет на оплату» → в карточке 1С:Управление торговлей нет описания выставления счетов); в запуске `01a20fe5-…` тот же кластер был закрыт как `NON_PRODUCT` — диагноз спорный, решает человек |
| Руководитель e-com | Объём спроса, доля проблемных и спасённых поисков, конверсия, вилка эффекта в заказах и рублях, стоимость эксплуатации | «Аналитика» (роль руководителя: доля спасённых), «Экономика»; вилка в рублях — `GET /api/effect` (на экране пока только доля) | Вилка на mock-логах за 30 дней (расчёт): консервативно 116 заказов / 6,28 млн ₽ в месяц, базово 250 / 13,5 млн ₽, оптимистично 391 / 21,2 млн ₽. Вход — замеры: 3 200 поисков, проблемных 56,8 %, спасённых 91,4 % (106 из 116 запросов test, где B0 не нашёл релевантного, а B4 нашёл; 95 % ДИ 84,9–95,3 %), средний чек 54 175 ₽. Суммы велики из-за mock-логов с 57 % неудач и B2B-чека; фактический эффект — A/B в пилоте ([PILOT.md](PILOT.md)) |

## Нефункциональные требования

| Требование | Как закрыто | Подтверждение |
| --- | --- | --- |
| Время ответа | LLM только на маршруте D, кэш разборов | P50 ~24 мс, P95 ~30 мс на test (B4, локально); разбор моделью 2,55 с при промахе кэша |
| Работа без внешней модели | `LLM_MODE=off`, переключение без перезапуска (`POST /api/admin/llm-mode`); дневной бюджет LLM — сверх него тоже правила и кэш | Проверено вручную на 10 сложных запросах: все ответили; переключение и бюджет — Go-тесты |
| Защита от перегрузки | Лимит 600 запросов в минуту с адреса (429), срок обработки 25 с | Лимит — Go-тест; срок обработки — в коде, отдельно не тестировался |
| Объяснимость | Трасса каждого запроса: шаги, время, скор, отсечённое с причиной | Экран «Поиск», `GET /api/traces/{id}` |
| Стоимость | Учёт каждого вызова модели, месячные сценарии, CSV-экспорт (`GET /api/costs/export`) | 0,434 ₽ за запрос при 20 тыс. в месяц, 0,102 ₽ при 200 тыс. — [COSTS.md](COSTS.md) |
| Интеграция | Независимый HTTP API, не привязан к CMS | [openapi.yaml](openapi.yaml), [PILOT.md](PILOT.md) |
| Безопасность | См. [PILOT.md](PILOT.md#безопасность) | |
