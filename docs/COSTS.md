# Стоимость эксплуатации

Каждое число помечено: **замер** (журнал вызовов модели, журнал поисков или прогон), **расчёт** (формула над
замерами и допущениями) или **допущение** (наше предположение, его нужно заменить данными заказчика).
Шаблон расчёта организатора к моменту написания не получен; исходные числа для него отдаёт
`GET /api/costs/export` (CSV, у каждой строки — источник: `measured`, `assumed`, `request`).

Месячные цифры ниже сняты с `GET /api/costs`. Тот же расчёт показывает вкладка «Доказательства →
Стоимость» (`/proofs?tab=cost`) и CSV-экспорт: формула и входные величины у них общие. Гость видит ту же сводку без
журнала вызовов (`GET /api/costs/summary`): 438 поисков, средняя стоимость запроса
0,00928 ₽, без LLM 94,29 %.

## Цены моделей

Yandex AI Studio, прайс (в коде — `PricingVersion`), ₽ за 1 млн токенов:

| Модель | Вход | Выход | Где используется |
| --- | --- | --- | --- |
| Alice AI LLM Flash (`aliceai-llm-flash`) | 100 | 200 | Разбор маршрута D, агент |
| Qwen3.6 35B (`qwen3.6-35b-a3b`) | 200 | 300 | Резерв разбора, LLM-судья |
| Alice AI LLM (`aliceai-llm`) | 500 | 1 200 | Не используется |

Каждый вызов модели пишется в `llm_usage`: токены, задержка, стоимость по прайсу, статус. Провайдер часть
входных токенов отмечает как закэшированные (1 072 из 1 181 на разборе); мы считаем их по полной цене —
консервативно.

## Из чего складывается запрос

Модель вызывается только на маршруте D и только при промахе кэша разборов. Маршруты A, B, C стоят 0 ₽ за
LLM.

| Величина | Значение | Тип | Источник |
| --- | --- | --- | --- |
| Доля маршрута D | 19,6 % (44 из 224 поисков) | замер | живые поиски, `search_events`, `source = live` |
| Доля попаданий в кэш разборов | 79,4 % (27 из 34 разборов) | замер | разборы маршрута D: кэш / (кэш + модель) |
| Стоимость разбора моделью | 0,137 ₽ (0,96 ₽ на 7 разборов) | замер | `llm_usage` живых поисков, с повторами и резервом |
| Онлайн-LLM на один запрос | 0,0056 ₽ | расчёт | 0,196 × (1 − 0,794) × 0,137 ₽ |
| Задержка разбора | медиана 2,55 с, максимум 3,58 с | замер | 10 сложных запросов, живые вызовы |
| Повтор из кэша | ~32 мс, 0 ₽ | замер | те же 10 запросов, 10/10 из кэша |
| Резерв Qwen3.6 35B | 0,289 ₽, 0,9 с на разбор | замер | 2 запроса |

Живые поиски — это поиски при разработке и показе, многие повторяются, поэтому доля кэша на них
завышена. Для сверки на test-наборе с весами частот маршрут D — 23,6 % поисков (замер). Верхняя граница без кэша — в таблице «Месяц». На данных магазина обе доли нужно
измерить заново.

Стоимость агента почти не зависит от числа поисков: она растёт с числом разбираемых кластеров.

Автономный агент (контур автономии) — живые запуски на отдельной базе, 8 запусков ≈50,5 ₽; рубли запуска — сумма строк
`llm_usage` с его `run_id`:

| Запуск | Триггер | Стоимость, время | Тип |
| --- | --- | --- | --- |
| `01a212ba-…` | смена каталога: 65 алиасов, 240 подсказок, связи | 9,49 ₽; 151 с | замер |
| `01a212c1-…` | всплеск: один кластер исправлен, 2 задачи | 12,07 ₽; 86 с | замер |
| `01a212c7-…` | ночной: проверка эффекта (первый прогон регрессии на новой версии правил — разборы намерения в песочнице) | 12,30 ₽; 68 с | замер |
| `01a212c9-…` | ночной: проверка эффекта, пропуск по памяти | 0,06 ₽; 9 с | замер |
| `01a212c4-…` | «Разобрать» один запрос | 1,54 ₽; 28 с | замер |
| запросы «Разобрать», уже решённые поиском | `already_solved` без модели | 0–0,18 ₽ | замер |

На демо-базе три запуска «Разобрать» — 10,29 ₽ (0,18 / 4,70 / 5,41 ₽). Таблица «Месяц» ниже
посчитана с 35,70 ₽ за запуск (среднее трёх запусков контура поиска); экран берёт среднее всех завершённых
запусков. Запусков по расписанию на демо-базе ещё нет — их стоимость появится, когда расписание включат на стенде.

Бюджет одного запуска: 80 вызовов инструментов, 600 тыс. токенов, 40 ₽ (`AGENT_RUN_MAX_RUB`),
25 минут; у «Разобрать» — 3 минуты. Исчерпан — запуск останавливается с шагом «бюджет» и списком неразобранного.

## Контур коммерции: допродажи, оборудование, маржа

На поиске контур коммерции LLM не добавляет: стоимость запроса и формула месяца не меняются.

| Что | LLM | Стоимость и время | Тип |
| --- | --- | --- | --- |
| Запрос по оборудованию (парт-номер, числа с единицами, «X для Y») | не вызывается: разбор правилами, на маршрут D не уходит | 0 ₽ | по коду; на 381 запросе контура поиска шаг не срабатывает |
| Блок допродажи, строка обязательного, совместимость | не вызывается: готовые связи и правила | 0 ₽; шаг < 0,1 мс; P95 поиска на p2 с блоком 10,4 мс, без — 5,6 мс | замер, локально |
| Закупка под задачу, старшая редакция | не вызывается: шаблон по триггерам правилами | 0 ₽; шаг P50 13,7 мс, максимум 504 мс (холодный) | замер, локально |
| Рычаг маржи на витрине | не вызывается | 0 ₽ | по коду |
| Симуляция рычага (бэк-офис) | не вызывается | базовая выдача tune собирается в фоне ~20 с и кэшируется до смены каталога или правил | замер |

Агент в режиме «Коммерция» (живые запуски на mock-2):

| Этап | Значение | Тип |
| --- | --- | --- |
| Справочник связей: 3 находки → 3 правки | 4,64 ₽; 16 вызовов, 45 123 токена (`01a2120d-…`) | замер |
| Повтор после отката: 1 правка | 1,70 ₽; 6 вызовов, 16 706 токенов (`01a2120f-…`) | замер |

Статистика совместных покупок и настройка маржи агентом удалены в контуре доводки. Месячный расчёт берёт среднюю
стоимость всех завершённых запусков агента с ненулевой стоимостью — и поиска, и «Коммерции». Таблица «Агент» выше
снята до запусков контура коммерции; после них среднее на вкладке «Стоимость» ниже 35,70 ₽. Сколько запусков
«Коммерции» нужно в месяц на данных магазина, не измеряли.

## Сервер

| Объём | Конфигурация | ₽ в месяц | Тип |
| --- | --- | --- | --- |
| 20 тыс. запросов | 4 vCPU / 16 ГБ | 7 500 | допущение |
| 200 тыс. запросов | 8 vCPU / 32 ГБ | 15 000 | допущение |

Что измерено: локально весь проект в Docker (OpenSearch с heap 1 ГБ, PostgreSQL, API) занимает ~1,5 ГБ;
сервис моделей на Mac M4 — ~4,4 ГБ и не растёт после 150 запросов. На CPU (локально): вектор запроса 49 мс,
64 карточки — 1,6 с, реранкер на 20 текстов — 640 мс. Реранкер работает на маршрутах C и D (10 семейств на
запрос): на CPU это порядка 0,3 с к их времени ответа (расчёт: 640 мс на 20 текстов, допущение — время
линейно по числу текстов; на стенде не проверено).
Память и задержки на CPU стенда не измерены, цена сервера — ориентир, а не счёт.

## Месяц

Формула (та же в коде, на экране и в CSV): вызовов LLM = запросы × доля D × (1 − доля кэша); онлайн-LLM =
вызовы × стоимость разбора; агент = запусков × стоимость запуска; итого = сервер + онлайн-LLM + агент.

| | 20 тыс. запросов | 200 тыс. запросов |
| --- | --- | --- |
| Сервер (допущение) | 7 500 ₽ | 15 000 ₽ |
| Онлайн-LLM (расчёт по замерам): 809 / 8 088 вызовов | 111 ₽ | 1 111 ₽ |
| Агент: 35,70 ₽ × 30 / × 120 запусков (замер × допущение) | 1 071 ₽ | 4 284 ₽ |
| **Итого** | **8 682 ₽ — 0,434 ₽ за запрос** | **20 395 ₽ — 0,102 ₽ за запрос** |
| Итого без кэша, верхняя граница (расчёт) | 9 111 ₽ — 0,456 ₽ за запрос | 24 681 ₽ — 0,123 ₽ за запрос |
| Без сервера, с кэшем (расчёт) | 0,059 ₽ за запрос | 0,027 ₽ за запрос |

Главная статья — сервер (86 % месяца при 20 тыс., 74 % при 200 тыс.), затем агент. Онлайн-LLM на поиске —
1,3 % и 5,4 % месяца; без кэша — 5,9 % и 21,9 %.

На вкладке «Стоимость» сервер и число запусков агента — поля ввода с пометкой «допущение»; в API те же
допущения меняются параметрами `server_rub_20k`, `server_rub_200k`, `agent_runs_month`,
`agent_runs_month_200k`.

## Ограничители расхода

- Дневной бюджет LLM `LLM_DAILY_BUDGET_RUB` (по умолчанию 1 000 ₽, сутки по Москве, все вызовы). Сверх него
  маршрут D идёт на правилах и кэше, в трассе — причина `budget_exceeded`; новый запуск агента — 503, а
  запуск, упёршийся в бюджет посреди работы, останавливается с `budget_limit`.
- Режим без LLM (`LLM_MODE=off`, переключается без перезапуска через `POST /api/admin/llm-mode`): маршрут D
  на правилах и кэше, 0 ₽ на поиске. Качество разбора сложных запросов в этом режиме не измеряли.
- Лимит частоты: 600 запросов к `/api` в минуту с адреса (`RATE_LIMIT_PER_MIN`), сверх — 429.

## Что не входит в стоимость запроса

Прогоны оценки, LLM-судья и прогрев кэша — расходы разработки и подготовки, они учитываются отдельно
(`kind: eval`, `judge`, `warmup` в журнале). Для справки (замер): прогон судьи на 600 парах — 25,69 ₽
(0,043 ₽ за пару).

## Как удешевить, если понадобится

- Прогрев кэша: `go run . warmup --limit 100` заранее разбирает частотные запросы из журнала и наборов, повтор
  такого запроса покупателем стоит 0 ₽. Сколько это даёт на реальном трафике, не измеряли.
- Реже запускать агента: при 200 тыс. запросов 120 запусков — 21 % месяца.
- Свой GPU под модель при таких объёмах не окупается: LLM — меньшая часть месяца.
