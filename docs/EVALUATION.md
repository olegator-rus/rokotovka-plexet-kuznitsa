# Как мы измеряем качество

Правило: каждое число получено прогоном и воспроизводится командой. У прогона есть идентификатор, хэш набора, версия
правил и версия каталога. Файлы прогонов лежат в `data/eval/`, сводку показывает экран «Доказательства → На данных
заказчика».

Все числа первой части документа измерены на фиде заказчика: 136 040 предложений, 4 413 семейств. Вторая часть,
[«Учебный каталог»](#учебный-каталог), описывает прогоны на собственных данных команды. Учебный каталог остался как
вариант запуска без данных заказчика, и ставить его числа рядом с числами на фиде нельзя.

Наборы, которые команда видела, показывают, как поиск отвечает на знакомые запросы. Как он справляется с незнакомыми,
показывает только отложенный набор.

| Пары склонений | 35 пар | именительный падеж и словоформа | набор настройки |
| Продление и «по запросу» | 9 | продление Kaspersky на 100 узлов, Windows Server, сравнение цены за место | набор настройки |

Файлы наборов «по цели» лежат в `data/softline/eval/`. В разметке «по цели» у запроса есть ожидаемая целевая страница:
семейство, вендор, вендор с фильтром категории, категория, конкретное предложение или отметка «товаром отвечать
нельзя».

Агент SearchOps проверяет свои правки на 195 запросах: 17 эталонов и примеров из кейса и 178 соседей и запросов
набора понимания. Отложенный набор агенту был недоступен.

## Метрики

| Метрика | Что измеряет |
| --- | --- |
| Success@1 по целевой странице | Первая ссылка ответа совпала с ожидаемой страницей. Адреса сравниваются после нормализации: регистр хоста, схема, `www`, завершающий слэш, URL-кодирование, порядок параметров. Главная метрика на эталонах и отложенном наборе |
| Hit@4 | Нужная страница есть среди первых четырёх ответов |
| MRR@10 | Среднее значение 1 / место первой подходящей карточки в первых десяти |
| ≥4 разных семейств | Доля ответов, в которых не меньше четырёх разных семейств |
| Нарушения условий | Запросы с жёсткими условиями (продление, число мест, тип организации, срок), где карточка в первых десяти их нарушает |
| Hit@1 по семейству | Доля запросов с точным названием продукта, у которых первая карточка из нужного семейства, в любом варианте лицензии. Главная метрика на журнале поиска по фиду |
| NDCG@10 по семействам | Насколько порядок первых десяти близок к идеальному по разметке 0–3 |
| p50, p95 | Медиана и 95-й процентиль времени ответа сервера |

Метрики считает код на Go (`go run . eval`), языковая модель в подсчёте не участвует.

Полный продукт прогонялся в тёплом режиме, упрощённые конфигурации — в холодном. Время ответа полного продукта на
эталонах — 72 мс по медиане и 127 мс p95, на соседях — 59 мс и 119 мс (время сервера без сети).

Что видно по таблице. Текстовый поиск с нормализацией и словарём даёт 7 эталонов из 10, оставшиеся три добавляет
только выбор целевой страницы. Гибрид сам по себе точность на эталонах не поднял (6 из 10), зато дал четыре разных
семейства в каждом ответе. Простой текстовый поиск показывает четыре разных семейства только в 3 ответах из 10 на
эталонах: одно семейство с сотнями предложений занимает весь верх выдачи.

Соседи и набор понимания — наборы настройки. Правила правились на них до нуля промахов, поэтому 100 % на них
обобщением не являются. В каждом круге правок скрипты сравнивали каждый запрос «до» и «после» и считали сломанные
отдельно: во всех кругах их 0.

## Журнал поиска по фиду

Эталонов всего десять, поэтому нужен набор побольше и ближе к живому трафику. Он собран из журнала витрины на фиде:
897 поисков, 197 разных запросов. В набор вошли 180 запросов с частотой от двух. Это тестовый трафик агента и ручные
поиски разработчиков, а не запросы покупателей магазина. В 71 запросе из 180 продукт искали по точному названию, по
ним считается Hit@1 по семейству.

Правильных ответов для этих запросов никто заранее не задал, их пришлось разметить. Источников разметки два:

1. Клики на выдаче витрины. Заказ даёт оценку 3, корзина или запрос цены 2, клик 2 или 1.
2. Модель-судья qwen3.6-35b-a3b. Она вслепую оценивает первые десять позиций всех конфигураций, по одному товару на
   семейство; оценка семейства переносится на все его предложения. Оценку по кликам судья может повысить, но не
   понизить. Неразмеченная пара нулём не считается.

Судью калибровали на эталонах и их соседях, где правильный ответ известен: целевые товары получили от него высшую
оценку в 85,4 % случаев.

| Конфигурация | Hit@1 по семейству, 71 запрос | NDCG@10 по семействам | Пустых выдач | p50 / p95, мс |
| --- | --- | --- | --- | --- |
| B0, подстрока в названии (наша реконструкция) | 25,4 % | 0,106 | 72,2 % | 29 / 50 |
| B1, текст с нормализацией и словарём | 62,0 % | 0,476 | 3,3 % | 9 / 19 |
| B2, гибрид | 70,4 % | 0,750 | 0 % | 30 / 38 |
| B3, полный путь на правилах версии 1 | **85,9 %** | 0,771 | 10,0 % | 129 / 562 |
| B4, с принятыми правками агента | **85,9 %** | 0,777 | 9,4 % | 101 / 343 |

В набор входят 15 сервисных запросов и 6 запросов-шумов, для которых пустая выдача и есть верный ответ. Поэтому доля
пустых выдач у B3 и B4 не равна доле ошибок.

Оговорки к таблице:

- Судья ошибается и на эталонах: 14,6 % целевых товаров не получили от него высшую оценку.
- Клики собраны на выдаче витрины, то есть конфигурации B3. Разметка по кликам подыгрывает B3 и B4.
- Набор составлен из тестового трафика и проверок команды. Типичного покупателя магазина он не представляет.

## Отложенный набор

Все наборы выше команда видела. Поэтому главную проверку мы вынесли отдельно: до конца настройки были отложены 83
запроса с правильными страницами. Их не открывали ни участники, настраивавшие поиск, ни агент SearchOps.

**Как собран.** Набор намеренно труднее настоящего трафика. В него вошли виды запросов, на которых поиск по буквам
ошибается чаще всего. Половина набора (44 запроса) — искажённые названия по девяти вендорам из эталонов заказчика:
склонение, транслит, опечатка, чужая раскладка, название с условиями. Вторая половина (39) — остальной каталог:
словоформы из кейса, серверы, продукты без цены, вопросы покупателя и мусор. Ни одна формулировка не совпадает с 232
запросами открытых наборов, со словами словаря соответствий и со строками тестов. Правильная страница каждого запроса
сверена с фидом, разметку до прогона подтвердили два участника команды.

**Как считали.** Прогон один, после заморозки поиска, во всех четырёх конфигурациях. Кэш разборов, векторов и
реранкера был выключен. Ответ засчитан, только если первая ссылка совпала с ожидаемой страницей. Нужный продукт на
втором месте — промах. Нужный продукт первой карточкой, но со ссылкой на конкретную модель вместо раздела — тоже
промах.

Что видно по таблицам.

- Полный продукт привёл на ожидаемую страницу первым ответом в 66 запросах из 83. Текстовый поиск в 37, со словарём и
  векторами в 46–47. Остальное дают определение категории, условия из запроса и выбор целевой страницы.
- Свои 37 попаданий текстовый поиск во многом набирает там, где можно не искать: 14 из них приходятся на вопросы и
  мусор, где правильный ответ — не предлагать товар. Там, где страницу товара нужно найти (69 запросов), у него 23
  попадания, у полного продукта 54.
- На 42 запросах с искажённым написанием (склонения, транслит, опечатки, раскладка, словоформы) текстовый поиск
  попадает первым ответом в 9. Полный продукт в 38, а в первых четырёх ответах нужная страница есть во всех 42.
- На 44 новых формулировках по девяти вендорам эталонов результат 39 из 44, на остальном каталоге 27 из 39. Главный
  запас для роста — серверы и продукты без цены.
- Языковая модель понадобилась на 12 запросах из 83. Средняя стоимость запроса в прогоне 0,0227 ₽, и это оценка
  сверху: кэш разборов был выключен. 95-й процентиль времени приходится на запросы с разбором моделью.

**Промахи.** Их 17, и каждый разобран. В пяти первая карточка правильная, но ссылка целевой страницы ведёт уже или в
сторону: например, на конкретный сервер вместо раздела серверов. В шести нужная страница стоит на втором–четвёртом
месте: «vnc kbyr» — это «мтс линк» в английской раскладке, но первые три буквы совпали с названием продукта VNC, и он
встал первым. В шести покупатель не увидел нужного в первых четырёх ответах: «windows 10 pro», «виндовс сервер
стандарт», «autocad», «блок питания для сервера», «режим работы поддержки» и «кукуруза в банке».

**Решение о реранкере.** Правило записано заранее: реранкер остаётся, только если даёт прирост на отложенном наборе.
Тот же набор прогнан в полной конфигурации без реранкера: 65 из 83 против 66, в первых четырёх 76 против 77, MRR@10
0,872 против 0,882. По правилу реранкер остаётся. Разница в один запрос сопоставима с разбросом ответов языковой
модели на маршруте D, поэтому доказательством пользы реранкера мы её не считаем.

**Разница со ста процентами.** На наборах настройки у поиска 100 %, на отложенном 80 %. На первых правила правились до
нуля промахов, вторые поиск увидел впервые. Мы приводим оба числа. После прогона набор перестал быть отложенным: 17
промахов уходят в наборы настройки как список правок для следующего круга.

Набор лежит в [data/softline/eval/closed.jsonl](../data/softline/eval/closed.jsonl), отчёт со всеми 83 запросами — в
[CLOSED_SET_RUN.md](CLOSED_SET_RUN.md). На экране «На данных заказчика» итогам набора отведён отдельный блок (поле
`closed_detail` в ответе `GET /api/evaluations/feed`).

Полезность карточек блока «Дополните решение» для покупателя не размечалась: проверены правила блока, а не продажи.

в [REQUIREMENTS_MATRIX.md](REQUIREMENTS_MATRIX.md).

## Тесты кода

Метрики проверяют качество ответов, тесты проверяют, что код работает так, как описано. В каталоге сервисов 471
тестовая функция, у фронта 454 модульных теста. При последнем полном прогоне сквозных тестов прошёл 141, упало 0,
пропущено 38 по условиям окружения. Сквозные тесты проходят сценарии покупателя и сотрудника на трёх ширинах экрана.

## Проверка должна уметь падать

Проверку мы считаем работающей, только если показано, что она способна обнаружить нарушение.

| Проверка | Как устроена | Свидетельство срабатывания |
| --- | --- | --- |
| Параметры описания совпадают с кодом | тест сверяет 103 числовых параметра вкладки «Теоретические основы» с константами кода | поменяли порог в коде — тест падает, пока не поправлен текст |
| Проверки подбора до показа | ответ проверяется кодом до показа покупателю | проверки сняли 2 фразы модели, которые в варианте без проверок дошли бы до покупателя |
| Правила лицензий | код применяет правила базы знаний к каждой карточке | на первой карточке обычного поиска те же правила нашли 5 нарушений из 59 |
| Допуск регрессий агента | правка проходит, только если ни один из 195 запросов не ухудшился | на причину «только по запросу» правка словаря отклоняется кодом до прогона |
| Сверка ответа модели | каждый идентификатор из разбора сверяется с полным справочником | выдуманный вендор «отечественный» отброшен и превращён в фильтр «российское ПО» |
| Скрипты оценки | сравнивают каждый запрос «до» и «после», сломанные считают отдельно | во всех кругах правок сломанных 0 |

Требование относится и к самим метрикам. Первый подсчёт на фиде показал точный товар первым только у 13,7 % запросов.
Разбор промахов по одному показал, что ошибалась разметка: она не засчитывала правильный ответ, если первым стоял
другой артикул того же продукта. Мы перешли к счёту по семействам и поправили промпт судьи. С тех пор сначала
проверяем, может ли метрика засчитать правильный ответ, и только потом смотрим на поиск.

## Как воспроизвести

Команды запускаются из `backend/` с переменными `DATA_SOURCE=generic` и `DATA_MAPPING=../data/softline/mapping.yaml`.
Нужны `make db`, `make ml` и импортированный фид; порядок описан в корневом [README](../README.md).

| Команда | Что проверяет |
| --- | --- |
| `go run . eval --set etalon,tz,neighbors,understanding --configs live` | Success@1 по целевой странице у полного продукта |
| `go run . eval --set etalon,tz,neighbors,understanding --cold --configs BM25,B1,B2,live` | сравнение с упрощёнными конфигурациями, холодный прогон |
| `go run . eval --set closed --file ../data/softline/eval/closed.jsonl --cold --configs BM25,B1,B2,live --report <каталог>` | отложенный набор; повторный прогон уже не является независимой проверкой |
| `go run . eval --summary <файл>` | сводка «На данных заказчика» по последним прогонам |
| `go run . guide-eval --runs 3 --report <файл>` | режим подбора и автопроверки; нужен ключ модели |
| `go run . traffic --flow ../data/softline/searchops_flow.jsonl --duration 12m --panel 0` | тестовый трафик для агента настоящими поисками |
| `make sets`, затем `make eval SET=test CONFIGS=B0,B1,B2,B3,B4` | наборы и разметка из журнала в базе, метрики по семействам; нужен журнал поиска в базе |
| `API=http://127.0.0.1:8088 python3 scripts/eval/<скрипт>.py` | проверки через HTTP: `customer_eval.py`, `neighbor_eval.py`, `understanding_eval.py`, `declension_eval.py`, `suggest_prefix_eval.py`, `upsell_eval.py`, `p63_eval.py` |

Часть Python-скриптов читает исходные наборы из рабочей папки команды, которая в открытый репозиторий не входит.

## Учебный каталог

До данных заказчика поиск строился на собственном учебном каталоге команды (`data/mock/`, описание —
[data/README.md](../data/README.md)): около 300 позиций, из них 72 единицы оборудования, размеченные запросы и 30 дней сгенерированных
логов. Сейчас это вариант запуска без данных заказчика: без переменной `DATA_SOURCE` импорт и API работают на нём.

Числа этого раздела нельзя сравнивать с числами на фиде. В учебном наборе правильный товар задан при генерации
запроса, поэтому результат показывает потолок метода на заведомо размеченных данных. Каталог, запросы и разметка на
фиде другие. Маржа, заказы и логи учебного каталога синтетические.

### Наборы и разметка

381 запрос в 185 группах формулировок, 13 типов: точные названия, артикулы, опечатки, раскладка, жаргон, назначение без
названия, условия лицензии, аналоги, товара нет в каталоге, жаргон вне словаря, нетоварные, шум, продления.

| Набор | Запросов | Для чего |
| --- | --- | --- |
| `tune` | 142 | Подбор порогов, весов, правил |
| `test` | 148 | Итоговые числа; на нём ничего не настраивалось, его тексты исключены из входа агента |
| `regression` | 78 | Проверка правок агента вместе с `tune` |
| `demo` | 13 | Сценарии показа, в метриках не участвует |

нашла заложенное, и разметку людьми не заменяет.
