# Как мы измеряем качество

Правило: каждая цифра получена прогоном и воспроизводится командой. У каждого прогона есть `run_id`, хэш
набора, версия правил, версия каталога и коммит; результаты пишутся в `data/eval/*.json` и таблицу `evaluations`.

Все цифры — на собственных mock-данных (`data/mock/`, описание — `data/README.md`). На данных магазина их
нужно пересчитать: методика и код готовы, разметку придётся сделать заново (см. [PILOT.md](PILOT.md)).

## Наборы запросов

381 запрос в 185 кластерах, 13 типов: точные названия, артикулы, опечатки, раскладка, сленг, назначение
без названия, условия лицензии, аналоги, товара нет в каталоге (`absent`), сленг, которого нет в словаре
(`alias_gap`), нетоварные, шум, продления. У каждого запроса есть частота в месяц (сумма — 2 976).

| Набор | Запросов | Кластеров | Для чего |
| --- | --- | --- | --- |
| tune | 142 | 70 | Подбор порогов, весов, правил. Настраиваемся только здесь |
| test | 148 | 70 | Итоговые цифры поиска. **Заморожен**: на нём ничего не настраивается; тексты test исключены из входа агента |
| regression | 78 | 36 | Проверка правок агента (вместе с tune) |
| demo | 13 | 9 | Сценарии показа, в метриках не участвует |
| holdout_week | по журналу | — | Эффект правок агента: реплей поисков последней недели журнала, которую агент не видел (см. «Эффект агента») |

**Набор контура коммерции `p2`** — 120 запросов: лицензии (`p2_license`, 20), парт-номера (`p2_mpn`, 20),
характеристики (`p2_specs`, 20), совместимость (`p2_compat`, 25), комплексная закупка (`p2_bundle`, 15), запросы,
где блока и шаблона быть не должно (`p2_negative`, 20). У запроса кроме оценок есть `expect`: ожидаемые фильтры,
якорь, обязательные дополнения, количество, шаблон. Отдельно — 149 размеченных пар «якорь × кандидат»
(`companion_pairs.json`) с классом: обязательное, совместимое, условное, несовместимое, неизвестное, дополнение,
старшая редакция, нерелевантное. Наборы контура поиска контур коммерции не менял.

**Деление по кластерам, а не по строкам.** Кластер — одно намерение и его формулировки: «тимвьюер»,
«teamveiwer», «teamviewer». Все формулировки кластера лежат в одном наборе, иначе настройка на одной
формулировке «подглядывает» в test через соседнюю. Внутри каждого типа кластеры делятся 40 / 40 / 20 %.

**Заморозка test.** Хэш набора `ae7a013f006b` пишется в каждый прогон. Правки, улучшившие tune, но не
повлиявшие на test, остаются и так и подписываются; правка, улучшившая tune, но ухудшившая test, откатана
(«основная редакция в семействе»: на test purpose −0,03).

## Разметка

Шкала 0–3: 3 — полностью соответствует намерению и условиям; 2 — подходящая альтернатива; 1 — частично или
сопутствующее; 0 — нерелевантно или нарушает обязательное условие.

Разметка построена правилами по полям каталога, а не руками по строкам (генератор детерминирован,
seed фиксирован). Договорённости: версия в запросе строгая («office 2021» не размечает 2024); явно названный
вендор строгий; количество и метрика лицензии — 3 при точном совпадении, 1 при другом количестве;
«отечественный» — строгий фильтр; для `absent` максимум 2 (аналог). Это разметка «по построению»:
она проверяет, что система нашла то, что мы заложили, и не заменяет разметку людьми.

## Метрики

Считаются на Go (`go run . eval`, `make eval`), без LLM в подсчёте.

| Метрика | Что измеряет |
| --- | --- |
| Пустые выдачи | Доля запросов без результата (и взвешенная по частоте) |
| NDCG@10, MRR@10, Recall@50 | Порядок и полнота относительно разметки |
| Точные на 1-м месте | Артикул или точное название — первым |
| Спасённые проблемные | Опечатки, раскладка, сленг, `alias_gap`, условия лицензии, аналоги: доля, где в топ-10 есть релевантный товар |
| Ложное спасение | Запросы `absent` и шум: выдача не пуста и не помечена ни «нет в каталоге», ни «аналог» |
| Нарушения условий | Запросы с условиями лицензии и продления: доля, где в топ-10 есть позиция нужного продукта, нарушающая условие (не то количество, метрика, тип) |
| P50 / P95 | Время ответа поиска |

Одной доли пустых выдач недостаточно: векторный поиск обнуляет её, показывая что угодно. Поэтому рядом
всегда стоит ложное спасение.

## Лестница конфигураций

| ID | Что включено |
| --- | --- |
| B0 | Точное совпадение подстроки в названии — **реконструкция исходной проблемы**, а не текущий поиск магазина |
| B1 | BM25 по нескольким полям + нормализация + словари |
| B2 | B1 + векторы BGE-M3 + RRF |
| B3 | B2 + атрибуты и разбор намерения + ранжирование с порогом и бизнес-слоем + реранкер на маршрутах C и D (по умолчанию) |
| B4 | B3 + принятые правки агента (действующая версия правил) |

B0–B3 — поиск без правок агента: они всегда считаются на исходных правилах (v1). Качество поиска оцениваем
по B0–B3 на test. Эффект агента (B3 → B4) — отдельно, на отложенной неделе журнала.

### Что изменили правки после обхода

Правки закрывали то, что видно человеку на витрине: недописанное слово, транслит, бизнес-лицензии при большом
количестве, категории по назначению, шум в хвосте выдачи (что именно — в [ARCHITECTURE.md](ARCHITECTURE.md)).
Настройка — только на tune; на test — один итоговый прогон.

| Набор, B3 | Было | Стало |
| --- | --- | --- |
| tune (142) | 0,947 | 0,951, ухудшений 0 |
| test (148) | 0,882 | 0,890 |
| holdout_week | 0,921 | 0,924 |
| regression (78) | 0,933 | 0,944 |

holdout_week после правок намеренно не записан в базу: на этом прогоне стоит доля спасённых на экране
руководителя, и она не должна сдвигаться от правок, которые настраивались уже после разреза журнала.

B1 и B2 на test тоже выросли (0,764 → 0,780 и 0,854 → 0,863): транслит и достройка последнего слова стоят в общей
нормализации. B3 по запросам: лучше «вмваре» (0 → 1,0), «антивирус для офиса» (0,57 → 0,68), «продлить
антивирус»; хуже одна формулировка «продлить антивирус» (0,973 → 0,963). Пустые, ложное спасение и нарушения
условий на test не изменились.

**Что стало хуже.**

- «корпоративная почта» и «почта для домена» на holdout_week и regression: 1,0 / 0,96 → 0,79. Слово «почта»
  теперь строго задаёт категорию «Почта и совместная работа», и Microsoft 365 E3 (по разметке — подходящая
  альтернатива, оценка 2) отсекается. Оставили: строгая категория по словам в сумме лучше на test, holdout_week и
  regression; мягкий вариант проверяли — «продлить антивирус» на test 0,89 → 0,73.
- «видеоконференции для компании» на regression: 1,0 → 0,88.
- «касперский на 10 пк»: Kaspersky Premium на 10 устройств теперь третий, после KES и KSOS. Для B2B-магазина
  бизнес-линейка первой при количестве от 10 — сознательное решение, а не ошибка.

**Реранкер.** До правок весь прирост B3 к версии без реранкера (NDCG 0,870 → 0,882, 7 запросов лучше, 1 хуже)
дал bge-reranker-v2-m3 на маршрутах C и D. Вес 0,45 подобран на tune (NDCG B3 0,933 → 0,947, 0 ухудшений).
Контрольный прогон с выключенным реранкером повторил прежние 0,870. Цена — задержка P95 на маршрутах C и D.

**Почему в таблице нет B4.** Действующие правила v2 содержат одну правку агента — «зуп» → 1С:ЗУП. Её
предложил запуск агента до того, как тексты test были исключены из его входа: запросы «зуп», «зуп базовая»,
«зуп корп» есть в test. На test B4 даёт NDCG 0,897 (прогон до правок, 3 запроса лучше, 0 хуже), но это не
независимая оценка, и мы её не используем как доказательство. Эффект агента — в разделе ниже.

Витрина ищет в конфигурации `live` — это B3 на действующих правилах, то есть B4 «сейчас». Поэтому «зуп» на
витрине находит 1С:ЗУП, а в столбце B3 этой таблицы — нет (v1).

### Ухудшения рядом с улучшениями

Каждый прогон считает по запросам, что стало лучше и что хуже относительно предыдущей ступени.

| Переход | Улучшились | Ухудшились | Примеры |
| --- | --- | --- | --- |
| B0 → B1 | 121 | 14 | хуже: «windows 11 pro» −0,35 |
| B1 → B2 | 41 | 14 | хуже: «кибер бэкап», «кибер бекап» −0,57 |
| B2 → B3 | 40 | 24 | хуже: «revit», «продление итс» −1, «р7 офис на 10 рабочих мест бессрочно» −0,86, «зуп» −0,63 (B3 на v1) |

0,856), `absent` (B2 получает баллы за близкие замены, B3 отвечает «нет в каталоге»). `alias_gap` — сленг,
которого нет в словаре; его закрывают правки словаря, то есть работа агента и менеджера.

## Контур коммерции: коммерческая лестница C0–C4

`make eval SET=p2` (`GET /api/evaluations/commerce?set=p2`, вкладка «До / После» → «Коммерция»). Флаги
включаются по одному на запрос, всё остальное — тот же код:

| ID | Что включено |
| --- | --- |
| C0 | Поиск контура поиска на действующих правилах (B4 / витрина `live`), всё новое выключено |
| C1 | C0 + оборудование: парт-номер, числа с единицами, совместимость с моделью, фасеты |
| C2 | C1 + блок допродажи |
| C3 | C2 + политика маржи (действующий вес) |
| C4 | C3 + принятые правки агента «Коммерция»: действующая версия связей и веса маржи по категориям |

C0–C3 идут на связях каталога, C4 — на действующей версии связей. Рядом считаются прогоны с одним изменением
(C0 + блок, C0 + маржа, C3 без оборудования, C3 без блока), чтобы был виден вклад каждого шага.

### Метрики блока и оборудования

| Метрика | Что измеряет |
| --- | --- |
| Нарушения совместимости | Показанные в блоке пары, размеченные как несовместимые. Блокирующая: должна быть 0 |
| Полнота обязательных | Доля размеченных обязательных дополнений, которые показаны (по семейству) |
| Покрытие блока | Доля якорей с размеченными дополнениями, у которых блок не пуст |
| Парт-номер на 1-м месте | Запросы `p2_mpn`: позиция с оценкой 3 первой |
| Разбор единиц | Шаг `hardware` разобрал ровно ожидаемые фильтры (ключ, оператор, значение) |
| Индекс показанной маржи | Маржа первых 10 позиций (перцентиль в категории, вес 1/log2(i+2)). На mock — синтетика |
| Точность блока по судье | Не считалась: судья на парах блока не прогонялся |

### Рычаг маржи

## Эффект агента

### Как устроена проверка

Агент предлагает правки словаря по журналу поисков. Чтобы оценка не подглядывала в ответы:

1. **Временной разрез.** Агент видит журнал только до начала отложенной недели — по умолчанию последних 7 дней
   журнала (`AGENT_HOLDOUT_FROM`, `AGENT_HOLDOUT_DAYS`). Граница считается по последнему историческому поиску
   журнала, и агент не видит ничего позже неё — в том числе живые поиски стенда. Чтобы агент разбирал свежие
   живые поиски, разрез задают датой (`AGENT_HOLDOUT_FROM=ГГГГ-ММ-ДД`) или выключают (`off`) — тогда отложенной
   недели для честной оценки нет. На mock-журнале агент видит 27.04–19.05, неделя 20–26.05 скрыта (871 поиск).
2. **Тексты test исключены** из всего, что видит агент: неудачные запросы, кластеры, переформулировки,
   «похожие успешные» (`AGENT_EXCLUDE_TEST=on` по умолчанию). На mock-журнале скрыто 146 текстов.
3. **Эффект правок — реплей отложенной недели** (набор `holdout_week`): все исторические поиски недели
   (без поисков с витрины в реальном времени) прогоняются через B3 и B4. Запрос — пара «текст × клиент», вес —
   число поисков за неделю. Разметка берётся из общего набора по тексту; неразмеченные поиски участвуют только в
   доле пустых.

Проверка правки внутри запуска (песочница) идёт на своих наборах tune и regression — test туда не входит.

## Как воспроизвести

```bash
make import                                   # каталог, логи, векторы
make eval SET=test                            # B0–B3 на test
make eval SET=contribution CONTRIB_SET=test   # вклад компонентов: лестница и полный путь без одного компонента
make eval SET=holdout_week CONFIGS=B3,B4      # эффект правок агента: реплей отложенной недели
cd backend && go run . eval --set test --with-proposal <id> --no-persist  # ждущая правка в песочнице
cd backend && go run . judge --set test       # LLM-судья, нужен ключ AI Studio
make eval SET=p2                              # коммерческая лестница C0–C4 (нужны набор p2 и companion_pairs.json)
cd backend && go run . margin --set tune      # рычаг маржи по всем положениям, в базу не пишет
```

Те же прогоны доступны на экране «До / После» (`/compare`) и через `POST /api/evaluations/run`.

## Ограничения

- Данные и разметка — свои, по построению. Абсолютные цифры на данных магазина будут другими.
- 148 запросов в test: разница в 0,01–0,02 NDCG — в пределах шума одного-двух запросов.
- Отложенная неделя на mock-журнале — 647 поисков: мелкие эффекты правок на ней неразличимы от шума.
- Поведенческие метрики (пустые, без клика, конверсия) на mock-логах — иллюстрация формы отчёта, а не
  оценка эффекта. Эффект измеряется A/B-тестом в пилоте.
- Контур коммерции: маржа и заказы синтетические — индекс маржи, оценка приоритета и модель эффекта допродаж это модель,
  а не факт. Ноль нарушений совместимости — на 149 размеченных парах, не гарантия на всём каталоге. Пары и `expect`
  размечены нами по правилам; слепой разметки людьми и судьи на парах блока нет.
