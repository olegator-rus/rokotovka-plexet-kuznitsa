# Подключение к сайту магазина

Как PLEXeT подключается к магазину и не заменяет корзину, карточку товара и оформление заказа. Методы описаны в
[openapi.yaml](openapi.yaml), как развернуть сервис — в [DEPLOY.md](DEPLOY.md). В графе «Статус» указано то, что есть в
коде сейчас: «нет» значит «нет», а не «почти готово».

Каталог подключён и проверен на полном фиде магазина, 136 040 предложений. С витриной магазина мы сервис не соединяли:
на стенде работает наша витрина, которая ходит в тот же API.

## Схема

```
           МАГАЗИН (остаётся у магазина: витрина, карточка, корзина, счёт, кабинет, Mindbox)
   фид каталога, события,          │                       ▲  выдача, подсказки, трассировка,
   журнал поиска                   ▼                       │  спецификация и запрос КП, сигналы спроса
           ┌──────────────────────────────────────────────────────────┐
           │ PLEXeT API: /search, /suggest, /consultant, /tz,           │
           │             /events, /quotes                               │
           │ OpenSearch, сервис моделей, PostgreSQL — свой сервер       │
           │ Бэк-офис SearchOps: агент, очередь, версии правил, откат   │
           └──────────────────────────────────────────────────────────┘
```

## Что читаем из магазина

| Данные | Зачем | Формат сейчас | Статус |
| --- | --- | --- | --- |
| Каталог: предложения, семейства, варианты лицензий, категории, вендоры | Индекс поиска, условия лицензии, вариант по умолчанию | Фид магазина (YML). Конвертер `scripts/data/softline_feed.py` переводит его в JSONL, поля сопоставляет `data/softline/mapping.yaml` | Есть, проверено на полном фиде. Другой каталог подключается своим файлом соответствия полей (CSV, JSON, JSONL, XLSX; пример — `data/mapping.example.yaml`) без правки кода |
| Цена и наличие | Цена на карточке, кнопка «Запросить цену» | Поля фида | Есть. Предложение без наличия или с нулевой ценой показывается «по запросу». Договорных цен нет, поиску они не нужны |
| Старая цена | Бейдж скидки | Поле `oldprice` фида | Есть: 32 предложения со скидкой |
| Адреса страниц семейств | Целевая страница ответа | `data/softline/family_urls.jsonl`, собирает `scripts/data/softline_family_urls.py` | Есть для 1 808 семейств из 1 809. При смене адресов на сайте сборщик нужно запустить заново. Надёжнее получать адреса от магазина |
| Акции | Строка акции под карточкой | `data/softline/promos.csv` | Есть: 9 акций с подтверждённым сроком, собраны в файл по разделу акций сайта магазина. Выгрузки акций от магазина нет |
| Документы совместимости | Основание рекомендации A в блоке «Дополните решение» | `data/softline/compat_docs.csv` | Есть: 41 запись, собраны с сайтов вендоров |
| Маржа и продажи | Слагаемые маржи и популярности в итоговом ранжировании | — | **Нет** в данных: маржа 0, популярность одинаковая. Формула примет эти поля без переделки |
| Заказы и история покупок | Частота совместных покупок, контекст клиента | — | **Нет** в данных. Блок назван «Дополните решение», пометка «Вы покупали» показана на демо-покупателях |
| События: клик, корзина, запрос цены, заказ — с `request_id` поиска | Отчёт о неудачных поисках, вход агента, оценка пилота | `POST /api/events` | Приёмник есть, его использует наша витрина. Витрина магазина события не шлёт |
| Журнал поиска за 30–90 дней | Наборы запросов из реального трафика, первые запуски агента | выгрузка событий | **Нет**: логов магазина у нас нет, агент работает на тестовом трафике |

Импорт строит новый индекс рядом и атомарно переключает его: поиск во время импорта не прерывается. Повторный импорт
запускает `POST /api/catalog/import` или команда `make import`. Словарь соответствий, документы совместимости, акции,
классы допродажи и база знаний читаются при старте API: после их правки нужен перезапуск API, а не повторный импорт.

## Что отдаём

| Метод | Что | Кто вызывает | Статус |
| --- | --- | --- | --- |
| `POST /api/search` | Выдача семействами с вариантом по умолчанию, целевая страница, тип совпадения у каждой карточки, блок «Дополните решение», трассировка | Сервер витрины или фронт магазина через свой прокси | Есть |
| `GET /api/suggest`, `GET /api/suggest/recommendations` | Подсказки при вводе: запросы, вендоры, товары. Без языковой модели и без векторов | Витрина | Есть |
| `GET /api/products/{id}` | Данные страницы товара | Витрина | Есть |
| `POST /api/consultant` | Ход ИИ-консультанта потоком событий | Витрина | Есть |
| `POST /api/guide/route`, `POST /api/guide`, `POST /api/guide/spec` | Прежний помощник подбора, запасной режим | Витрина | Есть |
| `POST /api/tz`, `GET /api/tz/operations/{id}`, `GET /api/tz/{hash}` | Поиск по ТЗ: загрузка документа, ход разбора, позиции | Витрина | Есть |
| `POST /api/events` | Приём событий витрины | Витрина | Есть |
| `POST /api/quotes` | Спецификация и запрос КП: позиции, количество, исходный запрос и параметры закупки | Витрина; дальше — CRM или спецификатор магазина | Приём есть. Передачи в CRM и спецификатор **нет**, формат нужно согласовать |
| Сигналы спроса | Чего нет в каталоге, что ищут и не находят, что есть только по запросу — задачи владельцам | Бэк-офис SearchOps | Есть в бэк-офисе. Выгрузки во внешние системы **нет** |

## Как подключаемся без замены корзины и карточки

1. **Теневой режим.** Сервер витрины параллельно с действующим поиском вызывает `POST /api/search` со своим сроком
   ожидания и пишет ответ в журнал. Покупатель видит прежнюю выдачу, в интерфейсе магазина ничего не меняется.
2. **Выдача.** Витрина рисует результаты своими карточками по идентификатору предложения из ответа. Кнопка «В корзину»
   ведёт в корзину магазина. Трассировку можно не показывать.
3. **Подсказки.** Тот же принцип: `GET /api/suggest` вместо действующего источника подсказок.
4. **События.** `POST /api/events` с `request_id` поиска. Без них не работают отчёт о неудачных поисках, агент и оценка
   пилота.
5. **Отказ.** Если API не ответил в срок, витрина показывает свой поиск: PLEXeT не становится точкой отказа магазина.
   Внутри PLEXeT отказ сервиса моделей или внешней модели тоже не останавливает поиск, выдача строится по тексту и
   правилам ([DATA_FLOW.md](DATA_FLOW.md)).

Время ответа полного продукта на эталонах — 72 мс по медиане и 127 мс p95 (тёплый прогон, время сервера без сети).
На запросах с разбором моделью без кэша оно доходит до двух секунд: на отложенном наборе p95 равен 1 994 мс. Срок
ожидания в теневом режиме нужно выбирать с учётом этого.

Бэк-офис (SearchOps, «Доказательства») работает отдельно от витрины и закрыт входом сотрудника или токеном
`BACKOFFICE_TOKEN`. Витрине вход не нужен.

## Что нужно от магазина

Обновляемая выгрузка каталога, журнал поиска, события с `request_id`, сервер или облако под API, OpenSearch и сервис
моделей, ответственные за причины неудач (администратор поиска, категорийный менеджер, каталог). Что из этого и когда
понадобится, описано в [PILOT.md](PILOT.md). Граница с Mindbox и спецификатором —
[MINDBOX_BOUNDARY.md](MINDBOX_BOUNDARY.md).
