# Mock-данные PLEXeT SearchOps

Свой набор данных на время до брифа организаторов: каталог B2B-магазина ПО, справочники, клиенты, наборы
запросов с разметкой и логи поведения за 30 дней. Формат описан в `docs/openapi.yaml` и `docs/ARCHITECTURE.md`, дополнения
контура коммерции (оборудование, допродажи, маржа) — и раздел «Контур коммерции» ниже. Разделы «Состав» … «Расширения
контракта» описывают данные контура поиска: они не менялись, test заморожен.
Названия ПО реальные; цены и артикулы — правдоподобные ориентиры, а не прайс магазина: часть артикулов
сгенерирована по шаблону вендора. Персональных данных нет.

## Как пересобрать и проверить

```
python3.13 scripts/data/gen_mock.py                  # пишет data/mock/*, детерминированно (SEED в gen_mock.py)
python3.13 scripts/data/validate.py                  # схема, ссылки, заложенные проблемы, логи
python3.13 scripts/data/validate.py --determinism    # + два прогона генератора побайтно равны data/mock
python3.13 scripts/data/validate.py --stats          # таблицы ниже
```

Только стандартная библиотека Python 3.13. Генерация детерминирована: генератор не зависит от
`PYTHONHASHSEED`, все случайные величины берутся из `random.Random` с фиксированным seed.

### Разметка (ground truth по построению)

Оценки ставятся правилами из `defs_queries*.py` по полям каталога, а не руками по строкам: 3 —
полностью соответствует намерению и условиям, 2 — подходящая альтернатива, 1 — частично или сопутствующее,
отсутствие в `judgments` — 0. Принятые договорённости:

- Точное семейство без условий: новые лицензии 3, продления 2, соседние редакции 1.
- Версия в запросе строгая: «windows server 2025» не размечает 2022, «office 2021» — не 2024.
  Исключение: Windows 11 Pro для «windows 10 pro» — 2, у неё есть право downgrade.
- Явно названный вендор строгий: в «касперский на 10 пк» Dr.Web не размечен.
- Количество и метрика: точное совпадение — 3, тот же продукт с другим количеством — 1. Позиция «поштучно»
  закрывает любое количество.
- «Отечественный», «в реестре» — строгий фильтр `origin` / `in_reestr`.
- Аналоги: заменители из `relations` — 3, сам исходный продукт — 1.
- `absent`: точного товара нет, максимум 2 (аналог из каталога, если он есть).
- `non_product` и `noise`: разметка пустая.
- Персонализация: «продлить антивирус» у клиента А — 3 только продление его KSOS на 10 ПК; у клиента без
  истории — 3 любое продление антивируса.

## Логи поведения (`events.jsonl`)

Логи имитируют текущий поиск магазина, а не наш. `results_count` считает реконструкция в `gen_mock.py`:
AND по словам названия, семейства, вендора, категорий и атрибутов, словарь `aliases.json`, исправление
раскладки (как на проде), без исправления опечаток и семантики. Числа и единицы лицензий, слова «аналог»
и «замена» игнорируются: «касперский на 10 пк» показывает все Kaspersky, «аналог фотошопа» — сам Photoshop.

- На каждый запрос ровно `freq` событий `search` с этим текстом за 30 дней (проверяется).
- Неудачный поиск (пусто или нет товара с оценкой ≥ 2 в выдаче) не даёт клика; с вероятностью 5–60 % (по типу запроса)
  за 6–50 с следует переформулировка: для `alias_gap` — в каноническое название, для `absent` с аналогом —
  в аналог, иначе — в другую формулировку кластера. После `absent` иногда — `manager_request`.
- Удачный поиск: клик с вероятностью по типу запроса (exact 72 %, sku 85 %), позиция — место товара в
  выдаче текущего поиска; дальше корзина и заказ, для позиций «цена по запросу» — `price_request`.
  Клиент с историей чаще выбирает свой продукт. У client-b заказов нет.
- Будни плотнее выходных, рабочие часы по Москве. `client_id: null` — гость.

+ click` по позиции; позиция без событий — 0,01. `validate.py` проверяет монотонность.

### Договорённости контура коммерции

- Оборудование: `kind: "hardware"`, `sku: ""`, идентификатор — `mpn` (часть совпадает с вендорскими, часть
  сгенерирована по шаблону вендора). `license` у оборудования пустой (`type: null`), у сервисных пакетов —
  подписка на сервер со сроком. `in_reestr: true` у оборудования российских вендоров (YADRO, Аквариус, Элтекс)
  означает реестр российской промышленной продукции.
- `specs` — только числа с ключами из списка; перечислимые свойства (`memory_type`, `interface`,
  `drive_type`, `drive_form_factor`, `os`, `poe`) лежат в `attributes` и описаны в `attribute_definitions.json`.
  В описании атрибута, кроме полей, — `unit_convert` (`{"тб": 1000}` для ГБ, `{"квт": 1000}` для Вт) и
  `values` у перечислений.
- У ноутбуков ОС не называется в названии и описании (`attributes.os`: «без ОС» / «предустановлена»): иначе
  ноутбуки всплывали бы на замороженных запросах `windows 11 pro`.
- `compatible_with` у компонента — модели с правилом `verified` или `conditional`. Источник правила — документация
  вендора компонента; компонент одного вендора в сервере другого — `expert`. `source_url` — страница поддержки
  модели или вендора, не конкретный документ.
- `license_rules.json`: значение в `requires_attrs` — список через `|` или `">=anchor.version"`; необязательные
  `anchor_product` (правило только для позиции якоря) и `requires_family` (правило 1С).
- Разметка `p2`: для совместимости verified → 3, conditional → 2, unknown и incompatible не размечаются;
  снятая позиция — не больше 1. У запросов `p2` есть поле `expect` (только у них): ожидаемые `filters`
  (`key`, `op`, `value`, `value2`, `unit`), `quantity`, `mpn`, `compat_target`, `required`
  (`family_id`/`product_id`, `metric`, `quantity`), `no_required`, `existing_license`, `upgrade`,
  `incompatible`/`unknown` (чего не должно быть среди «совместимых»), `template_id`, `companions: null`
  (блок не нужен). Из него считаются `units_parse_acc`, `mpn_top1`, `required_recall`, `compat_violations`.
- События контура коммерции — сессии `s2-…`, дописаны после строк контура поиска и отсортированы по времени внутри своего блока.
  Строка заказа: `order_id`, `account_id`, `quantity`. `client_id` = `account_id` у известных клиентов
  (client-a, c, d, f); у остальных 40 аккаунтов (`acc-001`…`acc-040`) `client_id: null` — в `clients.json` их нет,
  чтобы не раздувать переключатель клиентов на витрине.
- Популярность новых позиций — та же формула по событиям контура коммерции с нормировкой на максимум контура поиска; популярность
  позиций контура поиска не пересчитывается.
- Совместные покупки: тест Фишера по заказам на уровне семейств. Пара «объяснена», если есть прямая связь или
  общий сосед по связям (память и диски одного сервера). `validate.py` проверяет, что среди необъяснённых пар
  с ≥3 аккаунтами, значимых с поправкой Бонферрони, первая — заложенная R750 ↔ Ippon Innova RT II, а остальные —
  её производные.
- Новые позиции видны и запросам контура поиска: CAL 2025 попадает в выдачу `windows server cal`,
  `cal на пользователя windows server 2022`, `rds cal` (test) и в несколько tune/regression/demo. В разметке
  контура поиска их нет (оценка 0) — это осознанная цена добавления CAL 2025.
